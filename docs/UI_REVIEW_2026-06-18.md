# UI/CSS Review - 2026-06-18

Purpose: audit the existing Clever Monkey frontend without changing Claude's core product architecture. The visual direction remains the current Kopay-style orange/neutral system; fixes should be scoped to layout, responsiveness, polish, and obvious UX friction.

## Method

- Product Design context gate checked. No saved Product Design user-context exists, so the repo's own tokens/components and current screenshots are the source of truth.
- Read shared UI primitives and layout hotspots: `components/ui/Modal.tsx`, `components/AuthModal.tsx`, `components/IdleStateView.tsx`, `App.tsx`, `pages/StudyPage.tsx`, `components/FileListPanel.tsx`, and global styles.
- Captured local Playwright screenshots at desktop, 390x844, and 360x640.
- Keep changes reversible and small; add Playwright coverage for visible layout contracts when practical.

## Findings

### P0 - Visible Mobile Auth Presentation

- Status: fixed in this pass.
- Evidence: Mobile auth at 390x844 rendered as a floating rounded card with about 115px top/bottom gaps over the landing hero. At 360x640 it nearly filled the screen but still had edge gaps and rounded corners, making the bottom feel clipped.
- UX issue: login/sign-up is a task flow, not a small confirmation. On mobile it should feel like a full-screen page with a clear close control.
- Fix: `Modal` now supports `mobilePresentation="fullscreen"`, and `AuthModal` uses it. Desktop remains card-sized.
- Guardrail: Playwright asserts full-screen auth on the mobile project and card sizing on desktop.

### P1 - Generic Mobile Sheet Alignment

- Status: partially fixed in `Modal`.
- Evidence: `Modal` used `items-end` on the wrapper but `my-auto` on the dialog, so mobile sheets could center instead of anchoring to the bottom.
- Fix: default mobile sheet dialogs now use `mt-auto`; desktop keeps centered `sm:my-auto`.
- Remaining follow-up: custom modal implementations outside `Modal` still duplicate the old pattern.

### P1 - Custom Modal Implementations Duplicate Layout Risk

- Status: fixed in this pass.
- Evidence: `UpgradeModal`, `FileListPanel` delete confirmation, and `FlashcardsTab` settings modal each hand-roll fixed overlays with their own safe-area, radius, and scroll behavior.
- Risk: inconsistent mobile behavior and future fixes missing one modal.
- Fix: mirrored the updated mobile sheet classes exactly: no mobile edge gap, `mt-auto` bottom anchoring, `sm:my-auto` desktop centering, safe-area-aware max height, and token sheet shadow.
- Guardrail: actions and handlers were not changed; this is presentation-only.

### P2 - Token Consistency Drift

- Status: open.
- Evidence: a few classes still use arbitrary shadows such as `shadow-[1px_0_20px_0_rgba(...)]` and `shadow-[0_2px_10px_-3px_rgba(...)]` despite the token guideline limiting shadows to card/sheet/brand.
- Risk: low visual inconsistency, not a functional bug.
- Recommended action: replace with token shadows only when touching those components for nearby work.

### P2 - Mobile Landing Density

- Status: observed, not changed.
- Evidence: landing hero is tall on small screens, but it scrolls correctly and has no horizontal overflow.
- Risk: aesthetic only. The handwritten hero is part of the current brand moment.
- Recommended action: defer unless the user wants a denser mobile first viewport.

## Current Decision

P0 and P1 visible modal issues are now fixed. Keep P2 token consistency cleanup opportunistic unless a related component is already being edited.
